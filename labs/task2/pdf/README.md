підтримують запуск із кореня репозиторію, `labs/task2/` або `notebooks/`.

## Редагування та компіляція звіту

Редагуйте текст у `report/Task_2_Report.tex`, а фрагменти коду — у
`report/code/*.py`, потім виконайте:

```sh
sh labs/task2/pdf/report/build.sh
```

Ця команда підсвічує наявні Python-фрагменти та **компілює наявний LaTeX**.
Текст звіту й вихідні `.py` не перезаписуються, тому ручні правки зберігаються.
Потрібні Python із Pygments, XeLaTeX, latexmk і шрифти PT Serif, PT Sans,
Menlo (вони встановлені в перевіреному середовищі). На іншій системі можна
замінити три сімейства шрифтів у преамбулі на доступні з підтримкою кирилиці.
Для повторного експорту ноутбуків також потрібен Pandoc.

За замовчуванням скрипт використовує `.venv/bin/python` цього репозиторію;
інший інтерпретатор можна задати змінною `TASK2_PYTHON`.
Проміжні файли компіляції та підсвічені LaTeX-фрагменти містяться в `report/build/`; готовий PDF копіюється
в `output/pdf/`. Для компіляції збережіть структуру цього каталогу `pdf/`, оскільки
джерело використовує відносні шляхи до графіків. Окремі експорти ноутбуків
налаштовано для XeLaTeX зі шрифтами STIX Two Text, PT Sans і Menlo, які
підтримують кирилицю та потрібні символи.

Якщо змінюєте розрахунки, повторно запустіть відповідні ноутбуки, оновіть
числа й висновки у `.tex`, повторіть експорт та компіляцію. Перед компіляцією
виконайте `python labs/task2/pdf/report/prepare_code.py --from-notebooks`, щоб
оновити `report/code/*.py` з ноутбуків. Лише цей явний виклик перезаписує
збережені фрагменти коду. Текст звіту є
самостійним редагованим джерелом, тому числа в ньому не оновлюються автоматично.

Перевірений PDF має 23 сторінки: титул і 22 пронумеровані сторінки.
Заголовок титулу: «Завдання 2. Інференційна статистика». Колонтитул змінюється
за поточною частиною (1–5). Титул без видимого номера; далі сторінки нумеруються
послідовно від 1, а зміст посилається на ці номери. Оформлення оновлено

## Важливі уточнення результатів

- Gamma використовує **масштаб** 5; обсяги `5**1`–`5**8`; `seed=42`.
- Довірчі інтервали в частині 1 наближені для Gamma-даних, особливо при малих `n`.
- У частині 2 мінімізується від’ємна логарифмічна правдоподібність.
- Для `lilliefors(..., pvalmethod="table")` повернене 0.001 є нижньою табличною
  межею p-значення, а не його точним значенням.
- Частина 3(д) використовує лише вбудований statsmodels-тест, без ручної
  реалізації статистики. Для тесту частки дисперсію взято за нульовою гіпотезою.
- У частині 4 дисперсія 25 означає стандартне відхилення 5.
- У частині 5 оцінюється потужність `1-β` при `α=0.05`, а не сама `β`.
  Низькі значення при великих `df` пояснюються близькістю до нормального
  розподілу та консервативністю табличного калібрування при `n=80`.

Окрема перевірка рецензента в [validation/](validation/) дала фактичний розмір
0.034785 під нормальною нульовою гіпотезою. Її скрипт, фіксований seed 20261014
і JSON-результати збережено для перевірки цього пояснення. Це діагностика
реалізації, відокремлена від обов’язкового експерименту; вона не змінює
його seed, метод чи 59000 результатів.
